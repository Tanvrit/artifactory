# Tanvrit Artifactory — artifact/branding/release CDN for the whole fleet

Serves `artifacts.tanvrit.com`: release manifests, catalog, download redirects, and branding
assets for every Tanvrit product (`friendly`, `desipops`, `mandee`, `swyft`, `bharat-bandhu`,
`school`, `wedding`, `control`, `compute`). Cloudflare Worker + Pages + R2 (TypeScript/JS + Node
scripts). **Not a KMP/Gradle project** — no `gradlew`, no Kotlin models here. Also hosts the
**reusable per-OS release workflow templates** that every platform repo's CI calls into, and the
canonical design-token / icon generators.

> Repo-wide conventions are **not restated here** (ADR-037). See the workspace root `AGENTS.md`,
> `docs/development-patterns.md`, `docs/NAMING_CONVENTIONS.md`, `docs/SECURITY_GUIDELINES.md`.
> This file carries only Artifactory-specific facts, deltas, and gotchas.

## Build / Run / Test

Three independently-deployed surfaces, each with its own `package.json`. Node ≥ 20.

```bash
# Worker — Cloudflare Worker at artifacts.tanvrit.com/* (worker/wrangler.toml)
cd worker
npm install
npm run dev              # wrangler dev — local Worker
npm run deploy           # wrangler deploy → production Worker  (BLAST RADIUS)
npm run deploy:staging   # wrangler deploy --env staging
npm run tail             # live production logs

# Portal — Next.js static export → Cloudflare Pages (portal/)
cd portal
npm ci
npm run build            # next build; next.config.ts has output:'export' → portal/out/
npm run dev              # next dev, local
npm run deploy           # opennextjs-cloudflare build && deploy  (BLAST RADIUS)

# Scripts — token/icon generation + manifest/version tooling (scripts/, pkg @tanvrit/tokens)
cd scripts
npm install
npm run generate:tokens  # style-dictionary: branding/tokens/*.json → generated/{css,ts,kt,swift}
npm run generate:icons   # sharp/svgo: master SVGs → branding/icons/dist/ (all sizes/platforms)
npm run verify           # node verify-assets.js — asset presence/naming check
npm run sync             # node sync-to-apps.js — push tokens/icons into platform repos
```

There is **no test suite** and **no top-level `deploy.sh`** — `./deploy.sh` at the monorepo root
does not target artifactory. Deploys happen via CI (below) or the per-surface `npm run deploy`.

## Architecture — two parallel edge implementations (keep in sync)

The same CDN routing exists twice, deployed two different ways. If you change routing logic in one,
mirror it in the other:

| Path | Runtime | Deploy | Entry |
|---|---|---|---|
| `worker/src/index.js` | Cloudflare **Worker** (route `artifacts.tanvrit.com/*`) | `wrangler deploy` | `worker/src/index.js` |
| `functions/` | Cloudflare **Pages Functions** (bundled with portal) | Pages deploy | `functions/_middleware.js`, `functions/[product]/latest.json.js`, `functions/catalog.json.js`, `functions/brand/[[path]].js` |

Routes served: `GET /catalog.json`, `/{product}/latest.json`, `/{product}/{version}/latest.json`,
`/{product}/latest/{platform}` (302 → GitHub Release binary), `/{product}/{version}/{platform}`,
`/brand/{product}/{asset}`, `/brand/press-kit.zip`.

Storage is **R2-with-GitHub-raw fallback**: if the `ARTIFACTS` R2 binding is present, objects are
read from R2; otherwise the code falls back to `raw.githubusercontent.com/tanvrit/artifactory/main`.
Binaries themselves live on **GitHub Releases** (free bandwidth); the CDN only redirects to them.
`VALID_PRODUCTS` is duplicated in `worker/src/index.js`, `functions/_shared/constants.js`, and
`functions/_middleware.js` — update all three together when adding a product.

Cache TTLs (worker/src/index.js): catalog 30s, manifest 60s, binary-redirect 1h, branding 1yr
`immutable`. Branding assets are content-versioned, so the 1yr cache is safe.

## Manifests & catalog — bot-owned, do not hand-edit

`manifests/{product}/latest.json`, `manifests/{product}/{version}.json`, and `manifests/catalog.json`
are the **source of truth for released versions**. They are regenerated by
`.github/workflows/update-manifest.yml` → `scripts/update-manifest.js` and committed by `tanvrit-bot`,
then mirrored to R2 (`tanvrit-artifacts/...`). Edit the generator, not the JSON. The manifest workflow
fires on `repository_dispatch: update-manifest` (dispatched by each platform's release CI) or manual
`workflow_dispatch`. Payload carries `product`, `version`, `build`, `released_at`, `release_notes`,
`release_notes_hi` (English + Hindi notes).

## Branding pipeline

`branding/tokens/{base,semantic,products/*}.json` are the token **sources** (CODEOWNER-gated to
`@viveksingh`). `branding/tokens/generated/` and `branding/icons/dist/` are **generated outputs**
(CODEOWNER `@tanvrit-bot`) — never hand-edit; run `npm run generate:tokens` / `generate:icons` and
commit the result. `scripts/sync-to-apps.js` propagates generated tokens/icons into the platform repos.
The `@tanvrit/tokens` npm package (scripts/package.json) publishes generated tokens to GitHub Packages.

## Release-template ownership (cross-repo blast radius)

`.github/workflows/release-{android,ios,macos,windows,linux,web,firebase}-template.yml` are the
**reusable templates every platform repo's CI calls into** (see `docs/release-workflows.md`, the
canonical per-OS release doc). A breaking edit here breaks release CI across the entire fleet. The
old single `release-desktop-template.yml` matrix was retired (commit `53c7436`) in favour of one
self-contained file per OS. `scripts/bump-version.sh <product> <version>` edits `VERSION_NAME`/
`VERSION_CODE` in **other repos'** `gradle.properties` (mapping table in the script) — treat every run
as a cross-repo version change.

## Blast Radius — needs explicit authorization

Auto-mode does **not** override these. Confirm each time.

- **Never** run `npm run deploy` / `wrangler deploy` / `pages deploy` (worker or portal) unless the
  user explicitly says deploy — these ship live to `artifacts.tanvrit.com`.
- **Never** hand-edit files under `manifests/` (incl. `catalog.json`), `branding/tokens/generated/`,
  or `branding/icons/dist/` — they are bot/generator outputs; change the generator and regenerate.
- **Never** edit `worker/wrangler.toml` routes, `zone_name`, `[[r2_buckets]]` bindings, or the
  `tanvrit-artifacts` bucket name / account id without instruction — a wrong route can blackhole the CDN.
- **Never** edit the `release-*-template.yml` workflows without confirming the fleet-wide impact
  (`docs/release-workflows.md`); every platform repo's release CI depends on them.
- **Never** run `scripts/bump-version.sh` (writes `VERSION_NAME`/`VERSION_CODE` into other repos)
  unprompted; treat it as a cross-repo release action.
- **Never** commit secrets — no `CLOUDFLARE_API_TOKEN`, `CF_R2_TOKEN`, `CF_ACCOUNT_ID`, `.env*`,
  `*.pem`/`*.key`/`*.p8` staged. `git diff --cached` must contain no live tokens.
- **Never** bypass git hooks (`--no-verify`, `--force`) — investigate the failure instead.
- If routing logic changes, **never** update only one of `worker/src/index.js` / `functions/` — keep
  both edge implementations (and the triplicated `VALID_PRODUCTS`) in sync.
